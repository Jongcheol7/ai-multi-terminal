# 별도 콘솔 창 재발 확인과 명령 실행 우회 (2026-09-29)

## 확인

- 사용자 스크린샷에는 PowerShell 아이콘과 잘린 WindowsPowerShell 경로 제목을 가진 빈 Windows Terminal 창 두 개가 보인다. 스크린샷만으로 각 창의 PID는 확정할 수 없다.
- 9월 27일 적용한 프로필과 서버의 `--no-daemon` 설정은 유지되어 있다. 현재 CLI PID 13992의 실제 명령줄에도 `--no-daemon`이 있다.
- 현재 설치된 npm Codex CLI는 0.159.0이다. 별도 데스크톱 앱의 0.157.1 공유 서버도 실행 중이며 종료하지 않았다.
- 실제 프로세스 조회에서 CLI PID 13992가 `exec_command` 조회·검색용 PowerShell을 직접 생성하는 경로를 확인했다. `--no-daemon` 적용만으로 이 경로의 창 노출이 없어졌다고 결론 내릴 수 없다.

## 적용

- 이 세션의 Windows 명령 실행을 `tty: true`로 변경했다.
- `C:\Users\whdcj\.codex\AGENTS.md`에 모든 Windows `exec_command` 호출(중첩 호출 포함)에 `tty: true`를 지정하도록 추가했다. 9월 27일의 no-daemon 우회는 유지한다.
- 사용자 세션, 터미널 서버, MCP 서버, Windows 기본 터미널 설정은 변경하거나 종료하지 않았다.

## 검증

- `tty: true` 명령 두 개를 동시에 실행하면서 표시 중인 콘솔 창을 15회 조회했다.
- 15회 모두 기존 `Claude Terminal Server` 창 하나만 표시되었고, 추가 콘솔 창은 관찰되지 않았다.
- 원본 결과는 `tty-visible-windows.jsonl`, 읽기 전용 창 목록 스크립트는 `visible-consoles.ps1`에 있다. 스크립트는 창을 활성화·숨김·닫기하지 않는다.
- 이는 현재 명령 실행 경로에 대한 우회 검증이다. 모든 MCP/다른 앱의 자식 프로세스 창 노출까지 해결했거나 Codex 바이너리의 원인을 수정했다고 주장하지 않는다.
- 현재 세션에는 실행 방식 변경을 바로 적용했다. 앞으로 읽는 글로벌 지침에도 남겼으며, 앱 재빌드나 터미널 서버 재시작은 필요하지 않다.
