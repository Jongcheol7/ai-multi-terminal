# AI Terminal 작업 공간 업데이트 · 2026-10-04

## 적용

코드와 의존성 변경은 로컬에 반영했습니다. 사용 중인 서버·터미널은 재시작하거나 종료하지 않았습니다. 기존 작업을 마친 뒤 이 프로젝트의 서버를 다시 실행하고 브라우저를 새로고침해야 새 코드가 적용됩니다. 다른 세션의 서버를 종료하지 마세요.

기존 서버에서 만든 터미널은 새 세션 저장 구조로 이전되지 않습니다. 업데이트 후 만든 세션부터 다음 동작을 지원합니다.

## 화면과 조작

- 왼쪽 활동 메뉴와 프로젝트별 세션 목록, 상단 세션 탭, 하단 상태 표시줄.
- 프로젝트·세션 검색, 프로젝트별 새 세션, 세션 이름 변경·종료·기록 삭제.
- 첫 전송 내용을 세션 제목으로 사용하며 직접 이름을 지정할 수 있습니다.
- `Ctrl+Shift+P`: 명령·프로젝트·세션 검색. 입력창 밖에서 `Ctrl+B`: 사이드바 표시·숨김.
- 가로 분할, 2열 격자, 선택 패널 확대. 좁은 화면의 격자는 1열로 바뀝니다.
- Preset 목록은 화면 높이 안에서 스크롤되며 검색·즐겨찾기·최근 사용을 지원합니다.
- 입력 초안은 세션별로, 최근 전송 30개는 프로젝트·도구별로 이 브라우저에 저장합니다.
- 설정·세션 관리·클립보드의 실패는 커스텀 모달 안에 표시하고 다시 시도할 수 있습니다.

탭의 **×는 화면만 닫습니다.** 터미널은 서버에서 계속 실행되며 왼쪽 목록에서 다시 열 수 있습니다. 패널의 종료 버튼이나 세션 관리의 **터미널 종료**는 진행 중인 작업을 끝내므로 확인창을 표시합니다.

## 연결과 보관 범위

브라우저 연결과 터미널 프로세스의 수명을 분리했습니다. 탭 이동·새로고침·일시적 네트워크 단절 뒤 같은 세션 ID로 다시 연결하고, 연결이 끊긴 동안의 출력을 복원합니다. 돌아왔을 때 응답이 없는 연결은 감지해서 교체합니다. 전송 확인을 받지 못한 입력은 초안으로 남기며 자동으로 재전송하지 않습니다. 확인 응답은 터미널에 입력이 전달되었다는 뜻이며 AI 작업 완료를 뜻하지 않습니다.

서버가 켜져 있는 동안에는 기존 터미널 작업을 이어갑니다. **서버 재시작이나 PC 재부팅 뒤에는 저장한 화면 기록을 열 수 있지만 종료된 AI 프로세스를 이어 실행하지는 않습니다.** 새 작업은 새 세션으로 시작합니다.

세션 제목·목록과 화면 기록은 `.local/sessions/`에 저장되며 Git에서 제외됩니다. 화면 기록은 변경이 있으면 30초 간격, 연결 해제 및 명시적 종료 시 저장합니다. 갑작스러운 서버 종료 시 마지막 체크포인트 뒤의 출력은 누락될 수 있습니다. 실행 세션 복원은 스크롤백 최대 5,000줄, 디스크 기록은 최대 1,000줄을 사용합니다.

목록에는 **이 웹앱에서 만든 세션**이 표시됩니다. Claude Desktop 자체의 대화 목록을 가져오는 기능은 포함하지 않습니다.

## 크기 조절

브라우저와 서버의 xterm을 6으로 맞추고 라이브러리를 로컬에서 제공합니다. 크기 갱신 경로를 하나로 통합해 중복 전송을 막았으며, 복원 도중에는 크기를 바꾸지 않습니다. Windows ConPTY 정보를 양쪽에 전달하고 화면의 flex 크기 애니메이션을 제거했습니다. 패널 제목과 버튼, 입력 영역도 좁은 폭과 낮은 높이에 맞게 조정했습니다.

터미널 출력은 CLI가 커서 위치를 직접 제어하므로 일반 채팅 문단과 동작이 다릅니다. Claude·Codex의 실행 중 화면, 한글 긴 출력의 확대·축소는 실제 브라우저와 ConPTY에서 추가 확인이 필요합니다.

## 후속 수정: 새로고침 후 마우스 조작과 프로젝트 구분

- 사용자 실행 서버의 Chrome 페이지에서 마우스 캡처 활성 상태를 확인했습니다. xterm 직렬화가 마우스 추적은 복원하면서 SGR 입력 형식을 누락하므로, Windows ConPTY 화면 복원 시 SGR 형식도 적용합니다.
- 일반 왼쪽 드래그는 텍스트를 선택하도록 하고, Alt+클릭은 터미널 앱의 마우스 조작에 남겨둡니다. xterm 6 스크롤 영역을 덮어쓰던 이전 CSS도 제거했습니다.
- 프로젝트 제목에 밝은 파란색, 굵기 700, 배경 띠와 왼쪽 선을 적용했습니다. 세션 글씨는 기존 스타일을 유지합니다.
- 기존 Chrome 탭을 새로고침해 동일 세션 재연결과 실제 드래그 선택을 확인했습니다. 서버·PTY를 재시작하지 않았습니다. 휠의 실제 동작은 사용자 확인을 요청했습니다.
- 프런트엔드 검사 7개 통과. 새 회귀 검사에서 화면 복원 뒤 넓은 터미널의 휠 입력이 실제 SGR 보고 형식으로 생성되는 것을 확인했습니다.
- 로컬 확인 화면: `diagnostics/terminal-mouse-project-style-20261004.png`.

## 후속 수정: 선택 유지와 여백 없는 강조

- 텍스트 선택 중에는 해당 화면의 새 출력 표시만 보류하고 터미널 작업은 계속 실행합니다. 마우스를 놓아도 선택을 유지하며, ‘선택 해제 · 최신 출력 보기’, Esc, 새 클릭, 스크롤 또는 입력 재개 시 보관한 출력을 순서대로 표시합니다. 대량 출력의 메모리 사용을 제한하기 위해 대기 문자열이 8 Mi자를 넘으면 실시간 표시로 복귀합니다.
- xterm의 기본 셀 전체 강조 대신 공개 버퍼 API로 각 줄의 실제 글자 범위를 계산해 표시합니다. 줄 양끝 여백·빈 줄을 제외하고 한글과 넓은 글자의 셀 경계를 보존합니다.
- 실제 Chrome 페이지에서 드래그 후 선택 유지와 줄마다 다른 강조 폭을 확인했습니다. 기본 선택 렌더러의 셀 배경도 투명하게 설정했습니다.
- 선택 처리 회귀 검사 2개와 기존 프런트엔드 검사 7개를 실행했습니다. 로컬 검증 화면은 `diagnostics/terminal-text-selection-20261004.png`입니다.

## 추가 수정: 마우스를 놓은 뒤 Ctrl+C 전 선택 해제

이전 출력 보류 처리만으로는 부족했습니다. xterm의 SGR 마우스 이동 보고도 사용자 입력 이벤트를 발생시키므로 포인터 이동이 선택을 지웠습니다. 선택 중에는 공개 옵션 `disableStdin`으로 보고 전송을 막고, 선택 해제 시 원래 입력 상태로 돌립니다. 선택 중 자동 크기 갱신도 보류합니다.

Ctrl+C / Ctrl+Insert는 브라우저 기본 복사와 충돌하지 않게 처리하고 선택을 유지합니다. 복사 실패 시 오류를 표시하고 같은 선택으로 다시 시도할 수 있습니다.

## 후속 수정: 글자 가독성과 왼쪽 목록 접기

- 터미널 글자 크기는 사용자 요청에 따라 기존 14px를 유지하고, Consolas와 한글용 맑은 고딕을 지정했습니다. 줄 간격은 1.15, 기본 글자색은 `#e6e6e6`, 최소 명암비는 4.5로 조정했습니다. CLI가 지정하는 흐린 보조 문구는 유지합니다.
- 왼쪽 제목 옆에 `접기` 버튼을 추가하고 상단 버튼을 `목록 접기/목록 열기`로 표시합니다. 현재 선택된 왼쪽 메뉴 아이콘을 다시 누르면 목록을 접으며, 표시 상태를 저장합니다.
- 실행 중인 Chrome에서 글꼴 적용, 목록 접기/다시 열기와 작업 공간 너비 변경을 확인했습니다. 프런트엔드·선택 관련 기존 검사 9개와 구문 검사가 통과했습니다. 서버 재시작 없이 페이지 새로고침으로 적용했습니다.
- 확인 화면: `diagnostics/terminal-readability-sidebar-20261004.png`.

실제 Chrome에서 드래그 → 마우스 놓기 → Ctrl+C 후 클립보드 문자열 45자가 선택한 내용과 정확히 일치했고, 복사 후에도 강조 표시가 유지됨을 확인했습니다. 검증용 복사 뒤 원래 빈 클립보드로 복구하고 검증용 선택만 해제했습니다. SGR 이동 보고를 포함한 자동 검사 9개도 통과했습니다. 확인 화면: `diagnostics/terminal-selection-copy-20261004.png`.
